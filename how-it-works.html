How it works

Astrobyte is a command-line program. It runs when the owner starts it, either by hand or on a schedule set up on the same computer. There is no server in the middle and no web dashboard.

One run, four steps

  1. A task file is read. Each run is described in a short, readable text file: which episode, which step, which platform. Nothing is hard-coded into the tool itself.
  2. The tool authorises. It uses a Google OAuth token that the channel owner granted once, on this machine, for this channel. If a token is missing or expired, the tool stops and asks for re-authorisation instead of continuing.
  3. The work is done through the official APIs. Uploads, analytics reads and comment moderation all go through Google's own endpoints for the owner's own channel.
  4. The result is logged. Every run writes what it did and what came back, so the owner can check the outcome afterwards rather than trusting a silent success.

Google APIs used

APIWhat it is used forAccess
YouTube Data API v3 Uploading a video, setting its metadata and thumbnail, reading the channel's own video list and comment threads, and setting the moderation status of a comment on the channel's own video. Owner's own OAuth token, one channel only
YouTube Analytics API Reading the channel's own views, watch time, average view duration, average view percentage and subscriber figures for reporting. Owner's own OAuth token, one channel only

Authorisation scopes

The authorisation request asks for four scopes, and each one maps to a feature listed above:

  • Upload a video, so the tool can publish to the owner's own channel.
  • Read the channel's own data, so it can list its own videos and comments.
  • Manage the owner's own account, which the upload flow requires for thumbnail handling.
  • Read the channel's own analytics, so it can produce the reports.

The token is tied to one Google account and one channel. Revoking the grant in the owner's Google account immediately stops the tool from doing anything further.

What is stored, and where

Stored itemWhere it livesWhy
OAuth tokenLocal file on the owner's computerSo a run does not need the owner to sign in every time
Queue and schedule filesLocal files per dayTo know what has been published and what is still pending
Snapshot history of public figuresLocal filesTo compare today's channel figures against earlier readings
Run logsLocal filesSo each run can be verified afterwards

None of it is uploaded anywhere except where the run itself is meant to publish. There is no third-party analytics service, no advertising identifier and no tracking of anyone.

Failure behaviour

  • If authorisation fails, the run stops and reports it. It does not retry with a different account.
  • If a required check fails, the episode is not published. A wrong upload is worse than a late one.
  • If a scheduled task cannot complete, it reports the reason instead of finishing silently.
